TankEye-Iris 2.2.3 使用说明
========================

本文件必须按 UTF-8 读写，避免中文乱码。

一、首次使用
------------

1. 将 `TankEye-Iris_2.2.3.zip` 解压到本地磁盘，例如 `D:\TankEye-Iris_2.2.3`。
2. 不要直接在压缩包里运行程序。
3. 双击包根目录下的 `launch_tankeye_main_only.vbs`。
4. 第一次启动时，程序会在当前 Windows 用户桌面创建 `TankEye-Iris` 图标。
5. 后续可以双击桌面图标启动。

包根目录 VBS 和桌面图标都按 AutoStart 模式启动：自动加载模型，并在模型加载完成后请求进入已有 PLC 抓取联动。工程设置关闭“开机自启”时，程序仍会阻止自动进入检测。
默认启动会优先使用显卡加速；如果当前电脑显卡环境不稳定，程序会自动改用 CPU 启动，避免闪退。
新电脑第一次启动可能会多等几十秒；后续保留缓存后通常会更快。

二、图片检测
------------

1. 启动程序后，点击“加载图片”。
2. 可以选择包内 `samples\images\2.jpg` 作为演示图，也可以选择自己的图片。
3. “加载图片”使用后台线程读取，减少界面阻塞。
4. 点击“开始检测”执行 OBB/SEG 检测。
5. 程序会显示目标、分割区域、夹取射线、抓取点以及检测结果。
6. 后处理恢复旧版几何规则，执行 Canny 三边微调、矩形重建、二次垂足选 C、固定 45 px 生成 A、基础框重建和沿 AC 垂直方向 2 倍放大。真实夹爪框由工程设置中的夹爪长度/宽度、AC 角度加 90° 的方向和九点标定换算得到，不反向改写上游几何。类型显示补偿恢复为旋转后平移。
7. 如果夹爪长度/宽度为 0，或九点坐标转换未启用/无效，程序会保守判为不可抓。

三、PLC 与相机
--------------

- 默认运行包可用模拟 PLC 验证界面和模型加载。
- 连接真实 PLC、真实相机或真实设备动作前，必须确认现场设备安全，并由负责人明确允许。
- PLC 地址、端口和寄存器配置在 `config\tankeye.json` 中。
- 工程设置会保存到当前运行包的 `config\engineering_settings.ini`，不同版本运行包互不共用。

模拟 PLC + CPU 启动：

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\launch_tankeye.ps1 -Device CPU -SimulatePlc
```

四、管理员授权
--------------

首次创建管理员账号需要本机有效的 `config\admin_license.json`。

现场操作：

```text
1. 在管理员授权弹窗中点击“保存授权申请”。
2. 选择保存位置和文件名，得到 TankEye_admin_license_request_<机器码>.json。
3. 把授权申请 JSON 文件发给工程师。
4. 工程师生成 admin_license.json 后，把它放到运行包 config 目录。
5. 创建管理员账号时设置恢复问题和恢复答案。
```

普通检测不依赖管理员授权文件；没有有效授权文件时，不能创建管理员、不能登录管理员，也不能进入工程设置。
同一台电脑正常只需要申请一次管理员授权；后续重新打开软件时，放在 `config` 目录里的 `admin_license.json` 会继续用于管理员登录。
忘记管理员密码时，点击“忘记密码”，正确回答恢复问题后才能重置账号密码。重置时可以不填写新恢复问题和新恢复答案，不填会继续沿用原恢复问题和恢复答案；如果要更换恢复问题，必须两个都填。
正式运行包必须包含 `config\admin_auth.key`。

五、开机自启
------------

运行 `create_desktop_shortcut.ps1` 生成桌面图标时，默认同步创建当前用户开机自启入口。

当前自启合同：

```text
-StartupProfile AutoStart -StartupDelaySeconds N
```

含义：

- 自动加载模型。
- 模型加载完成后请求进入 PLC 抓取联动。
- 包根目录 VBS 与桌面图标使用同一 AutoStart 启动画像；手动运行 `launch_tankeye.ps1` 的默认行为仍是 Manual。
- 可在工程设置中关闭开机自启或调整延迟秒数。
- 自启入口使用当前用户 Startup 文件夹，不使用注册表、服务或计划任务。

六、OpenVINO 缓存
-----------------

第一次加载模型可能较慢，因为 OpenVINO 会编译模型并生成缓存。缓存目录为：

```text
openvino_cache
```

保留该目录后，后续启动或加载同一套模型通常会更快。

如确实需要清理缓存，可显式启动：

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\launch_tankeye.ps1 -ClearOpenVinoCache
```

正常使用不要加这个参数。

七、常见问题
------------

1. 图片中文路径加载失败：
   将图片放到纯英文路径，并把文件名改成英文或数字。

2. 管理员授权无效：
   检查 `config\admin_license.json` 是否存在、是否属于本机、是否由同一份 `config\admin_auth.key` 生成。忘记密码还需要正确回答恢复问题。

3. 第一次加载模型慢：
   这是 OpenVINO 首次编译模型的正常现象。保留 `openvino_cache` 后通常会改善。

4. 不想开机自启：
   进入管理员工程设置，关闭“开机自启”。

5. 仍然出现闪退：
   使用上面的“模拟 PLC + CPU 启动”命令复测，并把 `logs\tankeye_*.log` 最新日志发给负责人。

八、PLC 图片保留与错误图片
------------------------------

- `开始保存/停止保存` 只保存 PLC 触发的检测帧到 `images\`。
- 默认最多保留 1000 张 `tankeye_plc_*.png`，管理员可在工程设置中调整为 1~100000。只在新图写入成功后清理最旧图片，不删除其他文件。
- `保存错误图片` 在有最近 PLC 完成帧后可用，保存同帧原图和固定全显诊断图到 `error_images\`。
- `error_images\` 不参与普通图片 FIFO，程序不会自动删除其中的事故记录。
