# TankEye-Iris 五角色协作流程

更新时间：2026-08-03

本流程用于新功能、高风险 UI/CV/PLC 改动或需要跨模块判断的任务。它是仓内可复用协作规范，不是程序模块，也不依赖 README。

## 角色

- 产品经理：澄清现场用户目标、显示文案、默认行为、验收口径。
- 项目经理：拆小批次、识别依赖和风险、确保每批有验证闭环。
- CV 工程师：负责坐标转换、ROI 几何、检测结果与机械坐标语义。
- Qt 工程师：负责界面接入、绘制顺序、缩放适配、交互状态。
- 测试工程师：负责单元测试、渲染验证、真实程序启动和人工点检清单。

## 使用方式

1. 先读 `AGENTS.md` 和 `docs/project-memory/` 当前记忆。
2. 先做只读探索，确认源码事实和风险点。
3. 按五角色输出简短评审结论，重点回答“做什么、不做什么、怎么验”。
4. 用户确认关键选择后，再进入实现。
5. 实现必须小批次推进，完成后更新 `TASK_HISTORY.md`、`MEMORY.md`，必要时更新 `HANDOFF.md`。

## 默认原则

- 事实以源码、CMake、配置、脚本和测试为准。
- UI/CV/PLC 相关改动不能用假结果替代真实验证。
- 保护、坐标、PLC 语义必须优先保守，不能画或写入误导性结果。
- 角色流程用于减少盲区，不用于制造额外代码或文档负担。
