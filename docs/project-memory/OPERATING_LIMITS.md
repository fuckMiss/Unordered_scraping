## 高风险操作

以下操作必须先询问并获得明确同意：

- 安装、升级或卸载软件、驱动、SDK、Python 包、系统组件。
- 修改系统环境变量、注册表、防火墙、服务、计划任务、全局 Git 配置。
- 删除目录、批量移动文件、清理构建目录、重置 Git 历史、丢弃未提交改动。
- 连接真实 PLC、真实相机或会触发现设备动作的命令。
- 将密钥、模型、客户数据、运行日志或现场配置传到仓库外或网络位置。

## 工作节奏

- 大任务拆成小批次：探索、计划、实现、验证、记录。
- 每批只改必要文件，避免顺手重构无关模块。
- 开始修改前先确认 `git status --short`，识别已有用户改动。
- 读取和写入仓内文本文件默认使用 UTF-8；PowerShell 读写必须显式指定 `-Encoding UTF8`，脚本生成文本必须使用 UTF-8 写入，不能用系统默认 ANSI/OEM 编码处理中文文档、配置或界面文案。
- 完成一批后更新任务历史和动态记忆。
- 如需提交，提交信息必须说明相对上一版的变化：本次解决的问题、主要改动范围、关键验证结果；禁止使用无法说明差异的笼统信息，如 `update`、`fix`、`change`。

## 上下文管理

- 上下文接近 80% 时，先更新 `MEMORY.md` 和必要的 `HANDOFF.md`，再使用 `/compact`。
- 上下文即将耗尽或任务无法在当前会话完成时，必须把未完成任务、已改文件、验证状态、下一步命令写入 `HANDOFF.md`。

## 验证规则

- 模拟验证只能说明逻辑可能正确，不能替代真实程序或真实设备验证。
- 单个测试通过不等于整体成功；多文件、多功能改动必须跑集成测试或完整链路验证。
- 文档改动至少验证文件存在、路径正确、内容可读。
- 代码改动按风险选择验证：
  - 纯业务逻辑：对应单元测试 + 相关集成测试。
  - UI：构建主程序 + 实机启动观察或截图。
  - 启动/打包脚本：实际运行脚本并检查产物。
  - PLC/相机：优先安全模拟验证，再按用户同意连接真实设备验证。
